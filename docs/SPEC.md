# Todoリスト風ローグライクRPG 仕様書

## アプリが解決する問題

**ターゲット**: タスク管理を習慣化したいが続かない人（まず自分自身、のちにサービス展開）

| 問題 | 解決策 |
|---|---|
| 報酬が遠い | タスク完了で即コマンド解禁・ステータス変化が見える |
| 達成感が薄い | 今週の行動がそのままキャラのビルドに刻まれる |
| 継続できない | 「あのコマンドが欲しい」という具体的な逆引き動機が生まれる |

---

## 概要

日常のタスク管理をゲーム化したローグライクRPG。
タスクをこなすことでキャラクターが成長し、週末に強制的にダンジョンへ出発する。
繰り返し攻略することでメタ的に有利になる「パーマネントスキルシステム」が特徴。

## 週次サイクル

1週間を1サイクルとして繰り返す。

```
[月曜 0時] 新週スタート。ステータス・コマンドがリセット
     ↓
[月〜日]  タスクをこなす
          ├─ ステータス上昇（逓減方式、上限80）
          └─ コマンド解禁・強化（同カテゴリ重複は微小強化）
     ↓
[日曜終了] ステータス・コマンド確定（ロック）
     ↓
[職業選択] 解禁された職業候補から1つをプレイヤーが選択
     ↓
[出撃準備] パーマネントスキル装備（パッシブ2＋アクティブ1）
           ＋タスクコマンドを解禁プールから2枠選択
     ↓
[キャラクター生成] ステータス＋職業＋装備コマンド＋装備スキルが確定
     ↓
[ダンジョン出発（強制）] プレイヤーがダンジョンを攻略
     ↓
[クリア or 失敗] キャラクター消滅
     ↓
[翌月曜] 次のサイクルへ
```

## 主要機能

### 1. タスク管理

- タスクを自由に登録する
- LLMがタスクの内容を**分類**し、大きいタスクには**分解案**を出す（ユーザーが確認して登録）
- タスクを完了するとステータス上昇＋対応コマンドが解禁・強化される

#### タスク登録フロー

```
自由入力 →「プレゼン資料を作る」
   ↓ サーバ側のLLMが分類と分解案を返す
確認画面 → ☑ 構成を考える（仕事・作業）
           ☑ 参考資料を読む（学習・勉強）
           ☑ スライドを作る（仕事・作業）
   ↓ ユーザーが修正・取捨選択（カテゴリ変更・文言編集・追加・削除）
登録
```

- **分解するかはLLMが判断する**: 1回で終わる小さいタスクは分類だけを返し、工程が複数ある大きいタスクにだけ分解案を出す
- 分解案は**最大5個★**。サブタスクはそれぞれ単独で完了できる粒度にする
- 確認画面は必須（小型モデルの誤りをユーザーが直す前提）。分解せず元のタスクのまま登録することもできる
- LLMが使えないとき（通信エラー・タイムアウト）は、手動でカテゴリを選んで登録できる

#### 分解したタスクの数え方

- サブタスクは**1つずつ独立したタスク**として扱い、それぞれのカテゴリのステータスに加算する
- 元のタスクは**親**として残し、サブタスクの進み具合（例: 2/3）を表示する。親自体はステータスに加算しない（二重計上を防ぐ）
- 細かく分けた水増しは、既存の「1ステータス3件/日」と日次乗数で頭打ちになるので追加の対策はしない
- 分解するとカテゴリが分かれることが多く（上の例では仕事と学習）、使えるタスクコマンドの種類が増えてコンボを狙いやすくなる

#### タスク解析に使うLLM

- LLMは**サーバ側**から呼び出す。クライアントから直接は呼ばない（APIキーを端末に置かないため）
- 呼び出し部分は差し替えられるように作る。「タスク解析」の窓口を1つ用意し、その裏で API と自前の小型モデルを切り替える
- **使うモデルは比較して決める（未確定）**。同じテスト用タスク集で、分類の正しさ・分解の質・応答速度・料金を比べる。候補の調査結果は [`docs/MODEL_CANDIDATES.md`](MODEL_CANDIDATES.md)
  - 候補の一つ: Claude API の Claude Haiku 5.5（`claude-haiku-5-5`）。入力 $0.10 / 出力 $0.50（100万トークンあたり）、タスク登録1回あたり約 $0.0002
  - ほかの API のモデル、サーバで動かす自前の小型モデル（Qwen・Gemma 系など）も候補に入れる
  - 一人で使う段階では、使った分だけ払う API のほうが、固定費のかかる自前サーバより安くなりやすい
- モデルが決まるまでは、LLMなしで登録できる（カテゴリを手で選ぶ）
- 出力は JSON スキーマで形式を固定する（構造化出力）。返す項目は、カテゴリ、分解するかどうか、サブタスクの一覧（文言とカテゴリ）
- ユーザーが確認画面で直した結果を保存し、次回以降の例としてLLMに渡す。使うほど本人の分け方に近づく★

#### タスクカテゴリ一覧

| カテゴリ | 例 | 対応ステータス | 解禁コマンド（例） |
|---|---|---|---|
| 運動・スポーツ | ジム、ランニング、ヨガ | STR（力） | 重撃 |
| 学習・勉強 | 読書、資格勉強、語学 | INT（知力） | 弱点分析 |
| 健康・食事 | 料理、栄養管理、睡眠 | VIT（体力） | 回復食 |
| 仕事・作業 | 業務、報告書、会議 | DEX（器用） | 精密打撃 |
| 趣味・創作 | 絵、音楽、ゲーム制作 | MND（精神） | 奇跡 |

#### 不正対策

- **1日あたりの上限**: 同一ステータス（カテゴリ）のタスクは**3件/日**まで（超過分はステータスに反映されない）
- 一言入力などの摩擦を増やす対策は採用しない（継続性を優先）

#### 日付の区切り

- 1日は**ユーザーのタイムゾーンの 0:00** で切り替わる（初期値: 日本時間★）
- 1週間は**月曜 0:00** から始まる（ステータスのリセットと同じ）

#### 画面

| 画面 | 表示するもの |
|---|---|
| 今日 | 期限が今日のタスク、期限切れのタスク（「期限切れ」と表示）、今日の繰り返しタスク、今日完了したタスク |
| すべて | 未完了のタスク全部（期限が近い順。期限なしは最後） |
| 繰り返し | 繰り返しタスクの設定一覧 |

- 画面上部に**今週のステータス**（5種）と、カテゴリごとの**今日の残り加算回数**（3件中あと何件か）を常に表示する
- 「今日」画面から登録したタスクは、期限が今日になる

#### 期限

- タスクには期限（日付のみ）を付けられる。付けなくてもよい
- 期限を過ぎても消えない。完了するまで「今日」画面に「期限切れ」として残る

#### 繰り返しタスク

- 「毎日」または「毎週◯曜日（複数選べる）」で登録する★
- 該当する日になると、その日のタスクが自動で「今日」画面に並ぶ
- **やらなかった日の分は溜まらない**。その日が終わると未完了のまま消え、翌日に持ち越さない（習慣は溜めると負担になるため）
- カテゴリは登録時に決めた1つで固定。完了すると通常のタスクと同じくステータスに加算される（1日3件上限の対象）
- 繰り返しタスクは分解しない

#### 完了とステータス

- 完了した瞬間に、上がったステータスをその場で表示する（例: 「STR +5」）。その日そのカテゴリで4件目以降なら「今日の上限に達しているので加算なし」と表示する（完了自体はできる）
- **完了は取り消せる**。取り消すとステータスも元に戻る
- 今週のステータスは保存せず、**今週の完了記録から毎回計算する**（完了した順に成長テーブルと日次乗数を当てはめる）。取り消しや削除をしても数値がずれず、完了と取り消しを繰り返しても稼げない
- 完了済みのタスクを削除すると、その分のステータスもなくなる

### 2. キャラクター生成システム

#### ステータスと派生値

**基本ステータス（5種）**

| ステータス | 主効果 | 追加効果 |
|---|---|---|
| STR | 物理攻撃力 | DEFに貢献 |
| INT | 魔法攻撃力 | RESに貢献 |
| VIT | HPの基礎 | DEFに貢献、HP自然回復量 |
| DEX | 回避率・会心率 | 「逃げる」成功率 |
| MND | MPの基礎 | RESに貢献、MP自然回復量 |

**派生値（自動計算・タスク不要）**

| 派生値 | 計算式 | 用途 |
|---|---|---|
| DEF（物理防御） | (STR + VIT) / 2 | 物理ダメージ軽減 |
| RES（魔法防御） | (INT + MND) / 2 | 魔法ダメージ軽減 |
| HP（最大HP） | VIT × 5 + 100 | 0→100 / 40→300 / 80→500 |
| MP（最大MP） | MND × 4 + 20 | 0→20 / 40→180 / 80→340 |

> MND=0 のキャラはMP=20で低コストスキルを数回撃てる程度。MNDを伸ばすほど職業スキル・アクティブスキルの選択肢が広がる。

---

#### ステータス成長システム

- **上限値**: 80（全ステータス共通）
- **週次リセット**: 月曜0時にすべてのステータスが0に戻る
- 現在値が高いほどタスク1回あたりの加算値が少なくなる**逓減方式**
- さらに**同じ日に同ステータスを連続で上げると加算値が減る**（日次乗数）

**週次加算値テーブル（基本値）**

| 現在値 | 基本加算値 |
|---|---|
| 0〜19 | +5 |
| 20〜39 | +4 |
| 40〜54 | +3 |
| 55〜67 | +2 |
| 68〜79 | +1 |
| 80 | 上昇なし（上限） |

**日次乗数（1日あたり同ステータス3件まで）**

| その日のN件目 | 乗数 |
|---|---|
| 1件目 | ×1.0 |
| 2件目 | ×0.67 |
| 3件目 | ×0.33 |
| 4件目以降 | 無効 |

> 実際の加算値 = 週次基本値 × 日次乗数（端数は四捨五入）

**1日の加算量の目安（現在値帯別）**

| 現在値 | 1件目 | 2件目 | 3件目 | 日計 |
|---|---|---|---|---|
| 0〜19 | +5 | +3 | +2 | +10 |
| 20〜39 | +4 | +3 | +1 | +8 |
| 40〜54 | +3 | +2 | +1 | +6 |
| 55〜67 | +2 | +1 | +1 | +4 |
| 68〜79 | +1 | +1 | +0 | +2 |

**1つのステータスの伸び方（各日の終わりの値。テストで検証済み）**

| 1日の件数 | 1日目 | 2日目 | 3日目 | 4日目 | 5日目 | 6日目 | 7日目 |
|---|---|---|---|---|---|---|---|
| 1件 | 5 | 10 | 15 | 20 | 24 | 28 | 32 |
| 2件 | 8 | 16 | 24 | 31 | 38 | 44 | 49 |
| 3件（上限） | 10 | 20 | 28 | 36 | 43 | 49 | **55** |

**主要しきい値への到達目安**

| 目標値 | 最短（1日3件） | 1日1件のとき | 対応Tier |
|---|---|---|---|
| 15 | 2日目 | 3日目 | Tier 1（基本職） |
| 20 | 2日目 | 4日目 | Tier 3（複合職）の片方 |
| 30 | 4日目 | 7日目 | Tier 2（上級基本職） |
| 25×5全て | 3日目（計45件） | 6日目（計30件） | Tier 4（勇者） |
| 65 | **週内に届かない（最大55）** | — | Tier 5（最上級職）の片方 |

> ⚠ 日次乗数を入れた結果、1週間で1つのステータスが届く最大値は **55** になった。Tier 5 のしきい値（65）と上限値（80）には週の中で届かない。しきい値を見直すか、成長テーブル・日次乗数を見直すかは未決定（今後の検討事項）。

#### コマンドシステム

バトルで使える手札は **職業スキル**（職業由来）と **タスクコマンド**（今週のタスク由来）の2系統。

**設計方針: ハイブリッド**

- **職業スキル**が最低限の手札を保証する（タスクが偏った週でも戦える）
- **タスクコマンド**はボーナス手札で、コンボの主要な発動源
- 「全カテゴリやるとコンボ手数が増えてより強い」を維持しつつ、偏った週も成立させる

##### 職業スキル

- 各職業に**固定スキル4個（攻撃2＋変化2）**（職業決定時に自動付与）
- すべて週次リセット（職業は毎週選び直すため）

**スキル設計ルール**

- 攻撃スキルのダメージ参照は **STR（物理）か INT（魔法）のみ**（バトル計算式の原則と一致）
- MP効率は全職業ほぼ一定: **威力倍率 ≈ 1.0 + 消費MP × 0.1** のライン上に乗せる
- 専門職（戦士・魔法使いなど）は倍率が一段高く、特化した週の火力で必ず勝る
- ハイブリッド職は **STR技1つ＋INT技1つ** を持ち、倍率が一段低い代わりに職業らしい付随効果を持つ
- ランダム系効果は基本職には持たせない（上位MND職＝禅師の個性として温存）
- Tier 1 は確定済み（該当セクションに記載）。Tier 0 / 2〜5 は今後設計

##### タスクコマンド

- タスクを完了するとそのカテゴリに対応したコマンドが**解禁プール**に追加・強化される（週次リセット）
- **多様性 > スタック**: 異なるカテゴリの組み合わせ（コンボ）が最も強い
- **カテゴリ内バリエーション解禁**: 同カテゴリを3回こなすと2つ目のコマンドが解禁
  - 例: 運動を1タスク→「重撃」、3タスク→「連撃」も追加
- 解禁プール上限: 各カテゴリ最大2コマンド ×5カテゴリ = **最大10**

**装備枠（持ち込みは選抜制）**

- 出撃準備時に、解禁プールから**2枠**を選んで装備する（バトルで使えるのは装備分のみ）
- パーマネントスキル「戦術の心得」を習得すると**3枠**に拡張
- 装備枠が絞られているため、**狙うコンボを事前に決めて持ち込む**プランニングが生まれる

**タスクコマンド強化テーブル（同カテゴリ完了数による微小強化）**

| 同カテゴリ完了数 | 強化量（累計） |
|---|---|
| 1回目 | 基本効果 100%（ここが最大の価値）|
| 2回目 | +3% |
| 3回目 | +5%（＋2つ目のコマンド解禁） |
| 4回目 | +6% |
| 5回目以降 | 変化なし（上限） |

**コンボ例**

| 組み合わせ | 発動効果 |
|---|---|
| 重撃＋弱点分析 | 必殺の一撃（ダメージ×3） |
| 回復食＋精密打撃 | 集中療法（攻撃＋HP回復） |
| 奇跡＋重撃 | 渾身の一撃（高威力＋会心確定） |
| 弱点分析＋奇跡 | 大魔法召喚（全体攻撃） |

> ★ コンボの全種・発動条件は今後詳細設計する。装備2枠制のため、1回の出撃で狙えるコンボは実質1ペア（3枠なら最大3ペア）。

#### 職業決定ロジック

```
1. 全職業の条件を判定し、満たしているものをすべて列挙する
2. 一覧をプレイヤーに提示し、1つ選択させる
3. どれも満たさない場合は「冒険者」が自動適用される

例）STR=22, INT=21 の場合:
  ・魔法剣士（STR≥20 かつ INT≥20）  ← 複合職
  ・戦士（STR≥15）                   ← 基本職
  ・魔法使い（INT≥15）               ← 基本職
```

### 3. ダンジョン攻略

#### 基本ルール

- ローグライク風のランダム生成ダンジョン
- コマンド式ターン制バトルRPG
- キャラクターは**一度のダンジョン挑戦で消滅**（死亡・成功問わず）
- ダンジョンをクリアするとポイントを獲得

#### ダンジョン構成

```
[入口] → [フロア1] → [フロア2] → ... → [ボスフロア] → [脱出]
```

- 各フロアにはランダムなイベント（戦闘・宝箱・罠・休憩所）が発生
- フロア数はダンジョンの難易度によって変化
- ボスを倒すとクリア、HPが0になると失敗（キャラ消滅）

#### 自然回復（フロアクリア後）

戦闘中は自然回復しない。1フロアを抜けるごとに以下を回復する。

| 回復 | 計算式 | 例（ステ40） |
|---|---|---|
| HP回復 | VIT × 1.0 | +40 |
| MP回復 | MND × 0.5 | +20 |

> 戦闘中は回復しないため、リソース管理（アイテム・回復コマンド）が攻略の鍵になる。

#### バトルシステム

**ターン構造**: プレイヤー先攻固定。毎ターン以下の順で行動する。

1. プレイヤーがコマンド選択・実行
2. 敵が行動

DEXは行動順に影響しない（回避率・会心率にのみ作用）。

**ダメージ計算式（割合軽減方式）**

```
物理ダメージ = STR × 1.5 × 倍率 × (100 / (100 + DEF))
魔法ダメージ = INT × 1.5 × 倍率 × (100 / (100 + RES))

DEF = (STR + VIT) / 2
RES = (INT + MND) / 2

倍率: 通常攻撃 0.7★ / スキル・コマンドは各定義値（1.1〜2.2）
```

- 防御が高くてもダメージは0にならず、攻撃側のステータス差が常に効く
- DEF=80 でも軽減率は約55%（無効化しない）

**コマンド一覧**

| コマンド | 説明 |
|---|---|
| 攻撃 | 通常攻撃。**STRとINTの高い方を参照**（物理なら斬撃→DEF軽減、魔法なら魔弾→RES軽減）。倍率0.7★・MP0。どのビルドでも使える基礎打点 |
| タスクコマンド | 装備した2枠（パークで3枠）を使用。コンボ発動あり |
| 職業スキル | 職業固有スキル（4個）を使用。MPを消費 |
| アクティブスキル | 装備したパーマネント・アクティブスキル（1個）を使用。MPを消費 |
| アイテム | 所持アイテムを使用 |
| 逃げる | 戦闘から離脱（成功率はDEXに依存）|

---

### 4. お助けコマンド

- ダンジョン攻略中に**過去のキャラクター**を1回だけ呼び出せる
- 呼び出したキャラクターは1ターンだけ強力なアクションを実行する
- 使用後、呼び出したキャラクターは完全に消滅する
- 各ダンジョン挑戦につき**1回のみ**使用可能

---

### 5. メタプログレッション（パーマネントスキルシステム）

- ダンジョン攻略で**攻略ポイント**を獲得
- 攻略ポイントを消費して**パーマネントスキル**を習得（コレクションに蓄積）
- 習得済みスキルから、**キャラクター確定時に装備するものを選んで持ち込む**

#### ロードアウト（装備枠）

「時間をかけると強くなる」要素だが、強さの全てにはしない。以下の制約でバランスを取る。

- **パッシブ枠 ×2**: 常時効果（初期ステータス補正など）。習得済みから2つ選択
- **アクティブ枠 ×1**: バトル中に発動するスキル。**MPコスト必須**（その週のMNDが低いと撃てない＝週次プレイに依存）
- 何個習得しても持ち込めるのは **パッシブ2＋アクティブ1** のみ。蓄積では殴れない

#### パーマネントスキル例

**パッシブ系（パッシブ枠に装備）**

| スキル名 | 効果 | コスト |
|---|---|---|
| 鉄の意志 | 初期HP +10% | 50pt |
| 知恵の泉 | 初期MP +10% | 50pt |
| 集中の星 | MND +5 | 30pt |
| 先人の知恵 | ダンジョン開始時に回復アイテムを1個所持 | 80pt |
| 英雄の血 | お助けコマンドの効果が1.5倍になる | 100pt |
| 戦術の心得 | タスクコマンドの装備枠 +1（2→3） | 200pt |

**アクティブ系（アクティブ枠に装備・MPコスト必須）**

| スキル名 | 効果 | MPコスト | 習得コスト |
|---|---|---|---|
| 不死鳥の加護 | 一度だけHP1で復活 | 30 | 150pt |
| 時の砂 | 即座にもう1回行動する | 25 | 120pt |
| 浄化の光 | 状態異常を全回復＋小回復 | 15 | 60pt |

> ★ スキルの種類・効果・コストは今後拡充する。

## プロトタイプ

**`prototype/weekend-dungeon.html`** — 単一HTML・依存なし。ブラウザで開くだけで動作する。

週次サイクル〜ダンジョン攻略のループを一通り実装した検証用プロトタイプ。
バランスの体感検証はここで行い、確定した数値を本仕様書へ反映する。

**実装済み**

- 週プラン（1日3件上限・日次乗数・成長テーブル・おまかせプリセット週）
- 職業判定・選択（23職業の確定しきい値）
- タスクコマンド解禁＋装備2枠の選択
- Tier 1職業スキル20種 / コンボ4種 / 通常攻撃（STR・INT高い方×0.7）
- バトルシーン演出（スプライト・ダメージポップアップ・画面シェイク・撃破演出・ボス戦背景）
- ポケモン風メッセージ送り（1通ずつタイプライター表示・クリック/自動送り）
- ダンジョン7フロア（戦闘/宝箱/罠/休憩所・ボス「月曜の影」）

**プロトタイプ独自の仮値（SPEC未確定）**

- 会心率 5+DEX×0.5% / 回避率 DEX×0.4% / 逃走成功率 40+DEX×0.75%
- 敵能力値・敵HP式 / タスクコマンドの威力 / 攻略ポイント配分（フロア10pt・ボス50pt）

**演出の実装方針**

- 現段階: CSS/DOMアニメーション（本プロトタイプ）
- 次段階: Canvas/WebGL（Pixi.js等）によるパーティクル・スプライトシート演出
- グラブル級のキャラアニメはSpine/Live2D系アセット制作の領域。グランブルーファンタジー自体がHTML5ブラウザゲームであり、Web技術で到達可能なため**Unity等ゲームエンジンへの乗り換えは不要**と判断
